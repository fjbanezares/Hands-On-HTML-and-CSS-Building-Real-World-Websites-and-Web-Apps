🚀 Mi Primer CV Web, Control de Versiones con Git y Despliegue en GitHub Pages

Aprende el flujo de trabajo estándar en la industria del software: bifurcación (forking), control de versiones en equipo, maquetación con HTML5 y CSS3, y publicación en la nube.

🏛️ Univ.: Francisco de Vitoria 💻 Entorno: Antigravity IDE & Git Bash ⏱️ Entrega: URL Pages + Repo + Vídeo 1 min

🎯 Objetivos de la Práctica

✅ Comprender y ejecutar el flujo de Forking y Clonado.
✅ Dominar el ciclo: Ramas, Status, Add, Commit, Revert y Log.
✅ Comprender la especificidad CSS (ID vs Class vs Tag) y el uso de !important.
✅ Maquetar tu CV con posicionamiento CSS y publicarlo con GitHub Pages.
⚙️ Requisitos previos obligatorios:

Asegúrate de tener instalado Git (en Windows se usará Git Bash) y tener abierto tu proyecto en el IDE Antigravity.

1

Crear Cuenta en GitHub

Si aún no tienes una cuenta personal en GitHub, accede a github.com, regístrate de forma gratuita y valida tu dirección de correo electrónico.

2

Hacer un Fork del Repositorio del Profesor

💡 ¿Qué es un Fork y por qué es indispensable?
Un Fork crea una copia exacta de este repositorio en tu propia cuenta de GitHub. Como no tienes permisos de escritura directa en el repositorio del profesor, el fork te otorga tu propio entorno seguro para experimentar, romper código, crear ramas y desplegar en GitHub Pages sin interferir con el resto de compañeros.

Instrucciones:

  1. Entra en el repositorio original:
    🔗 https://github.com/fjbanezares/Hands-On-HTML-and-CSS-Building-Real-World-Websites-and-Web-Apps
  2. Arriba a la derecha, haz clic en el botón Fork.
  3. Verifica que el propietario seas tú y pulsa en Create Fork.
3

Clonar tu Fork en Local con git clone

git clone descarga los archivos y todo el historial de commits desde GitHub hacia tu ordenador local y configura la conexión remota con el alias origin.

# Abre Git Bash o tu Terminal y navega a tu carpeta de trabajo:
git clone https://github.com/TU_USUARIO/Hands-On-HTML-and-CSS-Building-Real-World-Websites-and-Web-Apps.git

# Entra en la carpeta del repositorio:
cd Hands-On-HTML-and-CSS-Building-Real-World-Websites-and-Web-Apps

👉 Abre esta carpeta en tu Antigravity IDE.

4

Crear tu Rama de Trabajo (`git branch` / `git checkout`)

Una rama (branch) representa un espacio de trabajo aislado. Permite modificar código sin poner en riesgo la rama principal (main).

# Crea y muévete a tu nueva rama (sustituye xxx por tus iniciales o nombre):
git checkout -b branch_alumno_xxx

# Verifica que estás en ella (aparecerá con asterisco verde):
git branch
5

Fundamentos Web: HTML, Especificidad CSS y la Regla `!important`

Nivel / Selector Ejemplo Prioridad Relativa
Estilo en línea (Inline) style="color: red;" Muy Alta (1000)
Selector de ID #header-id { ... } Alta (100) — Gana a clases
Selector de Clase / Pseudo .main-header { ... } Media (10)
Selector de Elemento / Etiqueta h1, p, div { ... } Baja (1)
⭐ Ejercicio de referencia: Abre en Antigravity el archivo 2. CSS Basics/specificity.html.
Observa cómo #header-id prevalece sobre .main-header y cómo las etiquetas <h1> heredan la cascada.
⚠️ Mención Especial a !important:

Al añadir !important a cualquier propiedad (ej: color: yellow !important;), el navegador rompe las reglas normales de especificidad y fuerza su aplicación.

  • ¿Por qué debes evitarlo en producción? Porque anula la cascada natural de CSS. Si necesitas modificar ese estilo en el futuro, tendrás que usar otro !important, volviendo el código ingobernable.
  • Tu tarea aquí: Pruébalo al menos una vez en specificity.html para comprobar cómo aplasta a los selectores #id. ¡Conócelo bien para no tener que abusar de él!

7

Flujo de Trabajo Git: git status y git add

Guarda los archivos modificados en Antigravity y dirígete a tu terminal de Git Bash:

# 1. Comprueba el estado (verás los archivos cambiados en ROJO):
git status

# 2. Añade los cambios al Staging Area (área de preparación):
git add .

# 3. Comprueba de nuevo (¡ahora aparecen en VERDE, listos para commit!):
git status
8

Guardar la Instantánea con git commit

Un commit es una captura histórica permanente que registra autor, fecha y un mensaje que explica el propósito del cambio:

git commit -m "feat: personalizar CV con datos de alumno_xxx y nuevos estilos"

Verás un resumen en la consola indicando el hash del commit y el conteo de insertions(+) y deletions(-).

9

Deshacer con git revert y tu Mejor Amigo: git log

↩️ ¿Qué pasa si te arrepientes tras hacer el commit?
Ejecuta git revert HEAD --no-edit. Esto creará automáticamente un nuevo commit inverso que deshace los cambios de forma segura sin destruir el historial ni causar problemas a tus compañeros.

🌳 Tu comando estrella para visualizar todo el árbol de ramas y commits:

git log --oneline --all --graph
  • --oneline: Visualiza cada commit resumido en una línea.
  • --all: Muestra todas las ramas (locales y remotas).
  • --graph: Dibuja las ramas y uniones en forma de árbol visual.
10

Subir tu Rama a GitHub con git push

Sincroniza tus commits locales con la nube de GitHub creando la rama remota:

git push -u origin branch_alumno_xxx
🔎 Comprobación clave: Vuelve a ejecutar git log --oneline --all --graph. Comprobarás que la etiqueta remota origin/branch_alumno_xxx apunta exactamente al mismo commit que tu rama local branch_alumno_xxx.
11

Publicar tu Web en GitHub Pages

  1. Abre tu navegador y ve a tu fork en GitHub.
  2. Entra en la pestaña Settings ➔ Menú lateral Pages.
  3. En Branch, selecciona tu rama: branch_alumno_xxx y la carpeta / (root). Pulsa Save.
  4. Espera unos segundos hasta que aparezca el enlace público de tu sitio.
🌐 Tu enlace final del CV será:
https://TU_USUARIO.github.io/Hands-On-HTML-and-CSS-Building-Real-World-Websites-and-Web-Apps/project_personal_CV/
